## 一、代码组织约定

### 1.1 文件头

**每一个** `.py` 文件都以相同的 LGPL 头开始：

```python
#
#   This file is part of do-mpc
#
#   do-mpc: An environment for the easy, modular and efficient implementation of
#        robust nonlinear model predictive control
#
#   Copyright (c) 2014-2019 Sergio Lucia, Alexandru Tatulea-Codrean
#                        TU Dortmund. All rights reserved
#
#   do-mpc is free software: ... (LGPL v3 全文)
```

新增文件时请复制这段头。

### 1.2 模块内部命名

| 约定 | 示例 |
|---|---|
| 实现文件以 `_` 开头 | `_mpc.py`, `_model.py`, `_mhe.py` |
| 公开 API 通过包的 `__init__.py` 重新导出 | `from ._mpc import MPC, MPCSettings` |
| 私有方法/属性以 `_` 开头 | `_setup_discretization()`, `_check_validity()`, `_prepare_nlp()` |
| Settings 类与主类同文件或独立 `_*settings.py` | `_controllersettings.py`, `_estimatorsettings.py`, `_ampcsettings.py` |

### 1.3 Settings 采用 `@dataclass`

v4.5.1 起，所有配置类都是 `dataclasses.dataclass`，每个字段后面紧跟一个**字符串字面量作为文档**（Sphinx 会自动抓取）：

```python
@dataclass
class MPCSettings(ControllerSettings):
    """Settings for :py:class:`do_mpc.controller.MPC`.
    ...
    """
    n_horizon: int = None
    """Prediction horizon of the optimal control problem.

    Parameter must be set by user"""

    n_robust: int = 0
    """Robust horizon for robust scenario-tree MPC.

    Note:
        Optimization problem grows exponentially with n_robust.
    """
```

**新增设置项时必须：**
1. 给出类型注解与合理默认值；
2. 紧跟字段文档字符串（含 `Note:` / `Warning:` 块）；
3. 若为必填项，在 `check_for_mandatory_settings()` 中加校验并 `raise ValueError`；
4. 可变默认值用 `field(default_factory=...)`（如 `nlpsol_opts: Dict = field(default_factory=dict)`）。

主类通过 property 暴露：

```python
@property
def settings(self):
    return self._settings

@settings.setter
def settings(self, val):
    assert isinstance(val, MPCSettings), ...
    self._settings = val
```

### 1.4 `flags` 状态机 + 断言式校验

do-mpc **不用异常体系**，而是大量使用 `assert` 做前置条件检查，配合 `self.flags` 字典强制调用顺序：

```python
self.flags = {'prepare_nlp': False, 'setup': False, 'initial_run': False}

# 在方法开头：
assert self.flags['setup'] == False, 'Cannot call .set_expression after .setup().'
assert isinstance(expr_name, str), 'expr_name must be str, you have: {}'.format(type(expr_name))

# 在方法结尾：
self.flags['setup'] = True
```

⚠️ **注意**：`assert` 在 `python -O` 下会被移除。这是 do-mpc 的既有设计取舍，改动时请保持一致风格。

### 1.5 docstring 风格

- Google 风格（`Args:` / `Returns:` / `Raises:` / `Note:` / `Warning:` / `Warnings:`），由 Sphinx 的 `napoleon` 扩展解析。
- 大量使用 **reST 交叉引用**：`:py:class:`、`:py:meth:`、`:py:func:`、`:py:attr:`、`:py:mod:`。
- 数学公式用 `.. math::` + LaTeX。
- 内嵌 **Graphviz** `digraph` 画流程图（如 `MPC` 类 docstring 里的 "Route to setting up the MPC class"）。
- 代码示例用 `::` 或 `.. code-block:: python`。
- 版本变更用 `.. versionadded:: >v4.5.1`。

```python
def set_rhs(self, var_name:str, expr:Union[castools.SX,castools.MX], process_noise:bool=False)->None:
    """Set the RHS of the model.
    ...
    Args:
        var_name: Name of the state
        expr: CasADi SX or MX expression
        process_noise: Flag to enable process noise

    Raises:
        assertion: var_name must be str
    """
```

### 1.6 类型注解

全面使用 `typing`：`Union`, `Optional`, `Dict`, `List`, `Tuple`, `Callable`。
`conf.py` 启用了 `sphinx_autodoc_typehints`，注解会渲染进文档。

### 1.7 CasADi 导入方式

⚠️ **不要**写 `import casadi.tools as castools`。统一使用兼容层：

```python
from .._casadi_compat import castools
# 或
from do_mpc._casadi_compat import castools
```

原因见 [`_casadi_compat.py`](../do_mpc/_casadi_compat.py) 的模块 docstring 与 [架构文档 § 十](02-架构与核心概念.md#十casadi-兼容层)。

## 三、测试

### 3.1 位置与运行方式

测试全部在 [`testing/`](../testing) 目录，使用标准库 `unittest`：

```bash
cd testing
python -m unittest              # 跑全部（CI 就是这么做的）
python -m unittest test_CSTR    # 跑单个模块
python -m unittest test_CSTR.TestCSTR.test_SX   # 跑单个用例
```

### 3.2 测试策略：**黄金结果比对 (golden-file regression)**

这是本项目测试体系的核心特点。`testing/results/` 里存放着**参考运行结果** `.pkl`，测试跑完后逐元素比对：

```python
# 跑 5 步闭环
for k in range(5):
    u0     = mpc.make_step(x0)
    y_next = simulator.make_step(u0)
    x0     = estimator.make_step(y_next)

# 与参考结果比对
ref  = do_mpc.data.load_results('./results/results_CSTR.pkl')
test = ['_x', '_u', '_time', '_z']

msg = 'Check if variable {var} for {module} is identical to previous runs: {check}. Max diff is {max_diff:.4E}.'
for test_i in test:
    max_diff = np.max(np.abs(mpc.data.__dict__[test_i] - ref['mpc'].__dict__[test_i]), initial=0)
    check = max_diff < 1e-8                      # ← 容差 1e-8
    self.assertTrue(check, msg.format(...))
```

**容差 `1e-8`** 非常严格 —— 这意味着任何影响数值结果的改动（离散化、场景树、缩放、约束组装）都会立刻被 CI 捕获。

**更新黄金结果**（当数值变更是**有意为之**时）：

```python
do_mpc.data.save_results([mpc, simulator, estimator], 'results_CSTR', overwrite=True)
```

每个测试文件里都有这一行，被注释掉了。取消注释跑一次即可刷新。⚠️ **务必确认改动是预期的，否则等于把 bug 固化成基准。**

### 3.3 `setUp` 的模块重载技巧

因为多个示例目录里都有同名的 `template_model.py`，测试用了这个模式避免模块串味：

```python
def setUp(self):
    default_path = copy.deepcopy(sys.path)
    sys.path.append('../examples/CSTR/')
    import template_model
    self.template_model = reload(template_model)     # ★ 强制重载
    sys.path = default_path                          # ★ 恢复路径
```

新增测试时请照抄这个模式。

### 3.4 SX / MX 双覆盖 + pickle 往返

## 四、持续集成

### [`pythontest.yml`](../.github/workflows/pythontest.yml) — 每次 push 触发

```yaml
on: [push]
jobs:
  build:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ["3.10", "3.11", "3.12"]
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-python@v4
      - run: pip install -r requirements_full.txt
      - run: |
          cd testing
          python -m unittest
```

**要点：**
- 三个 Python 版本矩阵：**3.10 / 3.11 / 3.12**
- 装的是 **full** 依赖（含 torch/onnx/asyncua），所以可选模块也会被导入
- 工作目录切到 `testing/` 再跑（测试内部用 `../` 相对路径）
- ⚠️ **没有装 HSL**，所以 CI 用的是默认 MUMPS 求解器
- ⚠️ **没有缓存** pip 依赖，每次全量安装 torch，CI 偏慢

## 六、打包与发布

### [`setup.py`](../setup.py)

```python
setup(
    name='do_mpc',
    version=__version__,                    # 从 do_mpc/_version.py exec 读入
    packages=['do_mpc','do_mpc.controller','do_mpc.differentiator',
              'do_mpc.estimator','do_mpc.model','do_mpc.sampling',
              'do_mpc.sysid','do_mpc.tools','do_mpc.opcua',
              'do_mpc.approximateMPC'],      # ★ 手工枚举，新增子包必须在此登记
    author='Sergio Lucia and Felix Fiedler',
    author_email='sergio.lucia@tu-dortmund.de',
    url='https://www.do-mpc.com',
    license='GNU Lesser General Public License version 3',
    long_description=open('README.md').read(),
    long_description_content_type="text/markdown",
    install_requires=read_file_lines('requirements.txt'),
    extras_require={'full': read_file_lines('requirements_full.txt')[1:]},
)
```

⚠️ **易错点：**
1. `packages` 是**手工列表**（不是 `find_packages()`）。新增子包（例如 `do_mpc/newfeature/`）**必须**手动加进去，否则发布的 wheel 里不含该模块。
   ✅ 当前状态：声明的 10 个包与磁盘上的 10 个**完全一致**（已用 AST 解析 `setup.py` 与遍历 `do_mpc/` 双向核对）。
   注意新增**模块**（如 `do_mpc/sysid/_anntomodel.py`）不需要登记，只有新增**包（目录）**才需要。
2. `read_file_lines` 遇到文件缺失只 `print` 不抛错，返回 `[]` —— 依赖会**静默丢失**。改 `setup.py` 后请检查构建日志。
3. `read_file_lines` **现在会过滤注释、空行与 `-r`/`-c` include 指令**。此前它把 requirements 文件逐行原样交给 `install_requires`，所以 requirements 文件里**不能写注释**（会被当成非法依赖说明符）。同时 `extras_require` 不再用 `[1:]` 位置切片跳过 `-r requirements.txt`，改为按前缀过滤。
4. `README.md` 含非 ASCII 字符（`Lüken`），因此读取时**必须显式 `encoding='utf-8'`**。在非 UTF-8 默认代码页的系统上，缺失它会 mojibake PyPI 描述或直接 `UnicodeDecodeError` 使构建失败。

### 6.2 已修的打包缺陷

| # | 缺陷 | 影响 | 修法 |
|---|---|---|---|
| 1 | **`packaging` 只在 extras 中声明**，但 `do_mpc/__init__.py` **顶层无条件 import** | `pip install do-mpc`（核心）在极简环境或 `--no-deps` 下会 `ModuleNotFoundError`。当前靠 `matplotlib → packaging>=20.0` 传递依赖兜住，属**潜在**而非现实故障 | 移入 `requirements.txt` 核心依赖，并从 `requirements_full.txt` 移除以免重复 |
| 2 | **`dist/` `build/` `*.egg-info/` 未被 gitignore** | `.gitignore` 里只有路径限定的 `documentation/build/`，**不覆盖仓库根的 `build/`**。构建一次就留下 3 个未跟踪目录，可能被误提交 | 补入 `dist/` `build/` `*.egg-info/` `.eggs/` |
| 3 | **`read_file_lines` 不过滤注释** | requirements 文件里一旦写注释就会被当作依赖说明符，导致安装失败 | 过滤空行、`#` 注释、`-` 开头的 include 指令；顺带去掉 `extras_require` 的 `[1:]` 位置切片 |
| 4 | **读 `README.md` 不指定编码** | 非 UTF-8 代码页下 mojibake 或构建失败（README 含 `Lüken`） | `open(..., encoding='utf-8')` |

### 6.3 仍未处理的打包现代化项

|---|---|---|

| **发布工作流用已弃用的直接调用** | `pythonpublish.yml` 里是 `python setup.py sdist bdist_wheel` | 改用 `python -m build`。构建时已实测到 `SetuptoolsDeprecationWarning: setup.py install is deprecated` |

## 七、给贡献者的实用提示

### 7.1 加一个新的控制器 / 估计器

1. 在对应子包新建 `_<name>.py`；
2. 继承合适的基类组合：
   - 基于优化的 → `class X(Optimizer, IteratedVariables)` 或 `class X(Optimizer, Estimator)`
   - 非优化的 → `class X(Estimator)` 或 `class X(IteratedVariables)`
3. ⚠️ **多继承顺序**：`Optimizer.__init__` 与 `IteratedVariables.__init__` 都会断言 `'model' in self.__dict__`。必须**先**给 `self.model` 赋值。参考 `MHE.__init__`：
   ```python
   def __init__(self, model, p_est_list=[]):
       Estimator.__init__(self, model)     # 先设 self.model
       Optimizer.__init__(self)            # 再初始化优化器
   ```
4. 在 `_<name>settings.py` 或同文件中加 `@dataclass` Settings 类；
5. 在子包 `__init__.py` 导出；
6. **在 `setup.py` 的 `packages` 列表登记**（若是新子包）；
7. 加示例到 `examples/<name>/`（遵循四文件模板）；
8. 加测试到 `testing/test_<name>.py`，生成黄金结果 `.pkl`。

### 7.2 加一个新的可选依赖

参考现有三个可选模块的模式：

```python
# do_mpc/__init__.py
if importlib.util.find_spec("mylib"):
    import mylib
    __MYLIB_INSTALLED__ = True
else:
    __MYLIB_INSTALLED__ = False

# do_mpc/myfeature/__init__.py
import warnings
from .. import __MYLIB_INSTALLED__
if __MYLIB_INSTALLED__:
    from ._impl import MyClass
else:
    warnings.warn('The myfeature feature requires mylib, which is not installed by default. '
                  'Please install the full version of do-mpc: pip install do_mpc[full]')
```

并把包名加进 `requirements_full.txt`。
