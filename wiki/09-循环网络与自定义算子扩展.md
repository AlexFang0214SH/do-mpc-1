## 一、核心范式：cell 化 + 隐状态入 `_x`

**这是整件事最关键的一点，也是最容易搞错的一点。**

MPC 的工作方式是在预测时域上**反复调用模型方程**滚动预测。所以它需要的不是"序列进、序列出"的 `nn.LSTM`，而是 **`LSTMCell` 的单步递推**；而递推所需的记忆，必须变成 do-mpc 的状态：

$$
x_k = \begin{bmatrix} p_k \\ h_k \\ c_k \end{bmatrix} \in \mathbb{R}^{\,n_{obs} + 2 n_{hid}},
\qquad
\begin{aligned}
h_{k+1}, c_{k+1} &= \mathrm{LSTMCell}(u_k,\ (h_k, c_k)) \\
p_{k+1} &= \mathrm{head}(h_{k+1})
\end{aligned}
$$

```python
model = do_mpc.model.Model('discrete', 'SX')
s_p = model.set_variable('_x', 'p', shape=(1, 1))
s_h = model.set_variable('_x', 'h', shape=(n_hid, 1))   # ★ 隐状态就是 do-mpc 状态
s_c = model.set_variable('_x', 'c', shape=(n_hid, 1))   # ★
s_u = model.set_variable('_u', 'u', shape=(1, 1))

h_next, c_next = lstm_cell_casadi(ca.vertcat(s_p, s_u), s_h, s_c, net.cell)
p_next = ca.mtimes(net.head.weight.detach().numpy(), h_next) \
       + net.head.bias.detach().numpy().reshape(1, 1)

model.set_rhs('p', p_next)
model.set_rhs('h', h_next)
model.set_rhs('c', c_next)
model.setup()
```

**为什么这样是对的**：do-mpc 会把 `set_rhs` 里的表达式在**每个时域步**上各实例化一次，这恰好就是 LSTM 沿时间的展开。不需要手写任何循环。

**这样做的额外收益**：

| 能力 | 说明 |
|---|---|
| **MHE 可估计隐状态** | `h`/`c` 是普通 `_x`，`do_mpc.estimator.MHE` 照常工作 |
| **鲁棒多阶段 MPC 照常可用** | 场景树对状态无特殊要求 |
| **自动微分免费获得** | CasADi 对整个 LSTM 单元求导，IPOPT 拿到的雅可比是精确的 |
| **约束照加** | `bounds['_x','h']` 等与普通状态无异 |

实测规模（`n_hid=16`，`n_horizon=15`）：

```
do_mpc Model built: n_x = 33  (1 observed + 16 h + 16 c), n_u = 1
MPC on the LSTM model: opt_x = 543 variables, opt_p = 34 parameters
```

> ⚠️ **必须用 `'discrete'` 模型。** 若用 `'continuous'`，正交配置会在 `n_horizon × collocation_ni × (collocation_deg+1)` 个配置点上各展开一遍 LSTM 单元，规模直接爆炸。

## 二、两条实现路径

### 路径 A：手工翻译权重 ✅ 推荐

不依赖 `onnx`，最可控。核心是**门序**：PyTorch 的 `weight_ih` / `weight_hh` 按行块 `[i, f, g, o]` 排列。

```python
def lstm_cell_casadi(x_sym, h_sym, c_sym, cell):
    w_ih = cell.weight_ih.detach().numpy()        # (4H, n_in)
    w_hh = cell.weight_hh.detach().numpy()        # (4H, H)
    b_ih = cell.bias_ih.detach().numpy().reshape(-1, 1)
    b_hh = cell.bias_hh.detach().numpy().reshape(-1, 1)

    gates = ca.mtimes(w_ih, x_sym) + b_ih + ca.mtimes(w_hh, h_sym) + b_hh   # (4H,1)
    H = gates.shape[0] // 4
    g_i, g_f, g_g, g_o = gates[0:H], gates[H:2*H], gates[2*H:3*H], gates[3*H:4*H]

    sigmoid = lambda z: 1 / (1 + ca.exp(-z))
    c_new = sigmoid(g_f) * c_sym + sigmoid(g_i) * ca.tanh(g_g)
    h_new = sigmoid(g_o) * ca.tanh(c_new)
    return h_new, c_new
```

GRU / RNN 同理，改门序与更新方程即可。

### 路径 B：ONNX 自动转换

```python
torch.onnx.export(cell, args, 'cell.onnx', input_names=['x','h','c'],
                  dynamo=False,               # ★ 必须显式关掉
                  opset_version=17)

conv = do_mpc.sysid.ONNXConversion(onnx.load('cell.onnx'))
print(conv)                                  # 先看输入名/形状/可查询的层名

x_row = ca.SX.sym('x', 1, n_in)              # ONNX 用行向量
h_row = ca.SX.sym('h', 1, n_hid)
c_row = ca.SX.sym('c', 1, n_hid)
conv.convert(x=x_row, h=h_row, c=c_row)
h_out, c_out = conv.output_layers             # LSTMCell 有两个输出

# do-mpc 用列向量 -> 在边界转置并把模型符号替换进去
h_next = conv[h_out].T
c_next = conv[c_out].T
for sym, target in ((x_row, ca.vertcat(s_p, s_u).T), (h_row, s_h.T), (c_row, s_c.T)):
    h_next = ca.substitute(h_next, sym, target)
    c_next = ca.substitute(c_next, sym, target)
```

### 两条路径完全等价（实测）

用**同一组权重**分别建两个 do-mpc 模型：

```
manual model n_x = 17   onnx model n_x = 17
max|rhs_fun(manual) - rhs_fun(onnx)| over 500 pts = 2.22e-16    ← 机器精度
max|u_manual - u_onnx| over 8 MPC steps          = 0.00e+00     ← 精确为 0
```

**8 步 MPC 的控制序列逐位相同。** 选哪条纯属工程偏好：A 无 `onnx` 依赖、归一化折进去更可控；B 免手写、能跟上框架变化。

### 路径 C：声明式构建器 `ann_to_dompc_model` ✅ **换模型时最省事**

路径 B 里那些转置、`ca.substitute`、逐个 `set_rhs` 的样板代码（约 25 行，且极易写错）已经封装进库：[`do_mpc/sysid/_anntomodel.py`](../do_mpc/sysid/_anntomodel.py)。

```python
model, converter = do_mpc.sysid.ann_to_dompc_model(
    Plant(),                                     # torch.nn.Module / .onnx 路径 / ModelProto
    x_spec  = [('p', 1), ('h', N_HID), ('c', N_HID)],   # ← 状态划分（隐状态在此提升为 _x）
    u_spec  = [('u', 1)],
    wiring  = [('xu', [('x', 'p'), ('u', 'u')]),        # ← 接线：ONNX 输入 ← 哪些 do-mpc 变量
               ('h',  [('x', 'h')]),
               ('c',  [('x', 'c')])],
    outputs = [(0, 'p'), (1, 'h'), (2, 'c')],           # ← 输出指派
    sample_args = (torch.zeros(1, N_IN), torch.zeros(1, N_HID), torch.zeros(1, N_HID)),
    input_names = ['xu', 'h', 'c'],
    verbose=True)
```

它做四件事：

1. **导出**：`source` 可以是 torch 模块（内部用 `BytesIO` 在内存中导出，不落盘）、`.onnx` 路径、或已加载的 `ModelProto`；
2. **接线**：按 `wiring` 把 do-mpc 列向量拼成 ONNX 行向量并 `ca.substitute` 进去；
3. **建模型**：声明 `_x`/`_u`、逐个 `set_rhs`、`setup()`；
4. **前置校验** ⭐ —— 这是它最有价值的部分。

**切换架构只改 spec，不改代码**（实测，见 [`onnx_path.py` part 4](../examples/lstm_surrogate_model/onnx_path.py)）：

```
built model: n_x = 17 (1 observed + 8 h + 8 c), n_u = 1     ← LSTM
same builder, GRU instead of LSTM: n_x = 9 (no cell state)  ← 只改了 x_spec/wiring/outputs
```

#### 前置校验：把晦涩报错变成可操作信息 ⭐

没有校验时，维度不匹配会在很下游以 CasADi 内部错误爆出：

```
RuntimeError: .../casadi/core/matrix_impl.hpp:344: Dimension mismatch. lhs is [2,1], while rhs is [16,1]
Exception: Error in powerIndex slicing for canonicalIndex ('x',)
```

有校验后：

```
wiring mismatch for ONNX input 'xu': it is 2-wide but the concatenation of
    [('x', 'p'), ('u', 'u')] is 4-wide.

wiring mismatch: ONNX output '8' ((1, 16)) is 16-wide but do-mpc state 'x' is
    2-wide. Graph outputs are [('8', (1, 16))]
```

`validate_wiring()` 还会检查：变量名重复、wiring 引用未声明的变量、同一 ONNX 输入被接两次、**有状态没有被任何输出驱动**、同一状态被驱动两次、输出指向非状态。

> 💡 我自己在做通用性实验时脚手架出了 bug（`deep()` 漏了最后一层 `Linear`），**正是这个校验一眼定位的**，否则会花很多轮去猜那个 `powerIndex slicing` 错误。

## 三、为什么序列 LSTM 走不通：CasADi 的 2-D 硬约束

**CasADi 矩阵严格是二维的**，而 ONNX 的融合 `LSTM` 算子作用于三维张量 `[seq_length, num_directions*batch_size, hidden_size]`。这个限制无法绕过：

```python
ca.SX.sym("x", 1, 3)     -> <class 'casadi.casadi.SX'>
ca.SX.sym("x", 1, 1, 3)  -> <class 'list'>      # 不是 SX！
```

实测四种导出对象的图规模与算子缺口：

| 导出对象 | 节点数 | 缺失算子 | 多输出节点 | 空字符串可选输入 |
|---|---|---|---|---|
| `nn.RNNCell` | 4 | **无** ✅ | 无 | 无 |
| `nn.LSTMCell` | 14 | `Constant`, `Split` | `Split` | 无 |
| `nn.GRUCell` | 16 | `Constant`, `Split` | `Split`×2 | 无 |
| **`nn.LSTM`（序列）** | **24** | `Constant`,`Expand`,`Gather`,`LSTM`,`Transpose` | `LSTM`（3 输出） | `LSTM`（slot 4） |

**结论：永远导出 Cell，不要导出序列模块。** Cell 在 ONNX 里没有对应算子，框架会把它拆成原语；序列模块则变成一个融合的三维 `LSTM` 算子外加一堆形状搬运子图。

上游化之后，序列 LSTM 会给出**清晰的错误信息**而不是令人困惑的 "Operation 'Constant' not implemented"：

```
Transpose with perm=[1, 0, 2] is not supported: CasADi is strictly
two-dimensional and cannot represent a 3-D permutation.
```

## 四、已支持的 ONNX 算子清单

`do_mpc.sysid.ONNXOperations`（源码：[`do_mpc/sysid/_onnxconversion.py`](../do_mpc/sysid/_onnxconversion.py)）

**共 37 个算子**，全部有测试覆盖（[`testing/test_onnx.py`](../testing/test_onnx.py)，106 个用例）。

| 类别 | 算子 | 备注 |
|---|---|---|
| 激活 | `Tanh` `Sigmoid` `Relu` `Elu` `LeakyRelu` `Softplus` `Softmax` `Clip` | ⚠️ `Relu`/`LeakyRelu`/`Clip` 有折点，导数不连续，IPOPT 可能收敛困难。做 MPC 代理模型请**在训练时**就选 `Tanh`/`Sigmoid`/`Elu`/`Softplus` |
| 算术 | `Add` `Sub` `Mul` `Div` `Pow` `Sqrt` `Erf` `Abs` `Neg` `Exp` `Log` `Sum` | `Erf` 用的是 `casadi.erf`，因此 **GELU 可转换** |
| 线性代数 | `MatMul` `Gemm` | `Gemm` 支持 `transA`/`transB`/`alpha`/`beta` |
| 归一化 | `BatchNormalization`（推理模式）`LayerNormalization` | 逐通道参数是 1-D `(C,)`，内部用 `_as_row` + `_broadcast_rows` 处理 |
| 规约 | `ReduceMean` `ReduceSum` | `axes` 支持 attribute（opset<18）与 input（opset≥18）两种形式；多轴规约明确报错 |
| 形状 | `Concat` `Split` `Transpose` `Unsqueeze` `Squeeze` `Slice` `Reshape` `Flatten` `Shape` `Identity` | 全部按 ONNX 规范实现并测试 |
| 常量 | `Constant` | 支持 tensor / int / float / ints / floats 五种 `value` 属性 |

**不支持**：`Conv` `MaxPool` `AveragePool`（需三维滑窗）、`Gather` `Expand`、融合的 `LSTM`/`GRU`/`RNN`（三维张量）、以及任何控制流算子。

> ✅ **轴语义已按 ONNX rank 正确解析**：`ONNXConversion` 用 `onnx.shape_inference` 记录每个值（含中间值）的 rank，`convert()` 派发前把偏移交给算子，`_resolve_axis()` 据此换算。这修掉了一类静默错误：`Unsqueeze` 之后的正数 `axis` 曾指向错误维度。详见 § 9.6。
>
> ⚠️ **CasADi 不做 numpy 式广播**：`(R,C)` 与 `(1,C)` 运算会抛 `Dimension mismatch for (x-y), x is RxC, while y is 1xC`。
> 与 `(R,1)` 列向量运算则可以。所以所有逐通道参数都要用 `_broadcast_rows` 显式平铺 —— 这是我实现 `BatchNormalization`/`LayerNormalization`/`Softmax(axis=0)` 时实测撞到的。

### 上游化修掉的七个缺陷

前四个是为支持循环网络而修，后三个是修 `Slice` 时顺带发现的**既有缺陷**——它们影响的不只是 LSTM，而是**所有现代 ONNX 模型**。

| # | 缺陷 | 原行为 | 现行为 |
|---|---|---|---|
| 1 | `Unsqueeze` | `return args[0]` —— **原样返回，静默错误**（源码挂着 `# TODO: Check if this is correct`） | 真正插入维度；rank > 2 时按规则降维或明确报错 |
| 2 | `Squeeze` | 同上 | 真正移除维度；rank 1 → 列向量，rank 0 → `(1,1)` |
| 3 | `convert()` 多输出 | 只存 `n.output[0]`，**下游节点找不到输入** | 按 `zip(n.output, out)` 全部注册 |
| 4 | `convert()` 空输入 | `all_values['']` → `KeyError` | 传 `None`，并给出清晰的未知输入报错 |
| 5 | **`Slice`** ⚠️ | 读 `attribute[0..2].ints`，这是 **opset ≤ 9** 约定。自 **opset 10** 起 `starts`/`ends`/`axes`/`steps` 是**输入** → 对任何现代导出都是 `IndexError: list index out of range` | 两种 opset 都支持；正确处理负索引、`INT_MAX`/`INT_MIN` 哨兵、`steps`（含负步长）、`axes` 缺省、rank>2 报错 |
| 6 | **`Concat`** | 无条件读 `attribute[0].i`；且 `axis in (0,2)` 一律 `vertcat`，**axis=2 静默产生错形状** | 用 `_attribute_int(...,'axis',0)`；0/-2 → `vertcat`，1/-1 → `horzcat`，其余明确报错 |
| 7 | **`Reshape`** ⚠️ | `data.reshape(tuple(shape))` —— **CasADi 是列主序，ONNX 是行主序**，元素被静默重排：`(3,4)→(2,6)` 得到 `[[0,8,5,2,10,7],[4,1,9,6,3,11]]` 而非 `[[0..5],[6..11]]` | 先按行主序展平再重建，与 numpy 逐元素一致；支持 `0`（复制输入维）与 `-1`（推断）；元素数不符明确报错 |

**#5 和 #7 是本次评估中最重要的发现**：

- `#5` 意味着 `do_mpc.sysid` 对**任何含切片操作的现代模型**都是直接崩溃的（Keras `Lambda(x[:, :2])`、多头注意力拆头、图像裁剪层……），而报错信息 `IndexError: list index out of range` 完全无法指向真因。torch 默认导出 opset 17+，tf2onnx 15+，**全部命中**。
- `#7` 更隐蔽：它**不报错**，只是静默给出错误的数值。

`Shape` 仍未改动，但 docstring 已明确标注它返回 Python **tuple** 而非 CasADi 值，因此"用形状参与计算"的图（`Shape → Gather → Concat → Reshape`，即导出器构造动态 reshape 的常见套路）无法转换。

### CasADi 2-D 降维规则

`ONNXOperations._reduce_to_2d`（算出目标二维形状）+ `_to_casadi_shape`（执行 reshape 并校验元素数）把 ONNX 形状映射到 CasADi 形状：

| ONNX rank | 处理 |
|---|---|
| 2 | 原样 |
| 1 | → `(n, 1)` 列向量 |
| 0 | → `(1, 1)`（仅当元素数为 1） |
| > 2 | **丢弃 size 为 1 的维度**直到 rank=2（从尾部优先）。丢弃单元素维不改变 CasADi 列主序的元素顺序，因此是无损的，正好覆盖 `batch_size == 1` 的常见情形 |
| > 2 且无单元素维可丢 | 抛异常，明确说明 CasADi 的二维限制 |

> ⚠️ **存活维度的位置很重要**：`(1, 12)` 降为**行向量** `(1,12)`，而 `(12,)` 降为**列向量** `(12,1)`。
> 把所有"只有一个非平凡维"的情况一律折成列向量会**静默转置行向量** —— 这正是 `Reshape` 最初实现里的第二个 bug。

实测：

```
Unsqueeze (2,3) axes=[0] -> (2,3)     # ONNX (1,2,3) -> 丢掉单元素维
Unsqueeze (1,6) axes=[0] -> (1,6)     # ONNX (1,1,6)
Unsqueeze (6,1) axes=[1] -> (6,1)     # ONNX (6,1,1)
Squeeze   (1,6) axes=[0] -> (6,1)     # ONNX (6,)   -> 列向量
Squeeze   (6,1) axes=[1] -> (6,1)
```

## 五、如何新增一个算子（扩展指南）

所有算子遵循**统一签名**：

```python
def OpName(self, *args, attribute=None):
    ...
```

- `args`：节点输入，按 ONNX 图中声明顺序。**可选输入以 `None` 传入**（图里是空字符串），实现必须容忍。
- `attribute`：原始 ONNX 属性列表（`onnx.AttributeProto`）。用内置辅助方法读取：
  - `self._attribute_int(attribute, 'axis', 0)` — 缺省时返回默认值
  - `self._attribute_ints(attribute, 'perm')` — 缺省时返回 `None`
- 返回：CasADi `SX`/`MX`/`DM` 或 `numpy` 数组。

### 单输出算子

直接返回结果即可，`convert()` 会注册到 `n.output[0]`：

```python
def Softmax(self, x, attribute=None):
    axis = self._attribute_int(attribute, 'axis', -1)
    e = casadi.exp(x - casadi.mmax(x))          # 减最大值保数值稳定
    return e / casadi.sum1(e)                   # 视 axis 选 sum1 / sum2
```

### 多输出算子

返回**长度等于声明输出数的 list/tuple**，`convert()` 会按 `zip(n.output, out)` 逐个注册：

```python
def MyMultiOut(self, x, attribute=None):
    return [part_a, part_b, part_c]
```

若输出个数**只能从节点的输出列表推断**（如 `Split` 不给 `split` 输入时的等分），则返回 `_SplitRequest` 标记，由 `convert()` 解析——因为只有它知道 `len(n.output)`：

```python
def Split(self, data, split_sizes=None, attribute=None):
    axis = self._attribute_int(attribute, 'axis', 0)
    sizes = None if split_sizes is None else [int(s) for s in np.ravel(split_sizes)]
    return _SplitRequest(axis, sizes, data.shape[axis])
```

### 不修改库的临时扩展方式

在库改动合并前，可以用子类化在自己的代码里扩展：

```python
from do_mpc.sysid import ONNXConversion, ONNXOperations

class MyOps(ONNXOperations):
    def Softmax(self, x, attribute=None): ...

class MyConversion(ONNXConversion):
    def __init__(self, model, model_name=None):
        super().__init__(model, model_name)
        self.operations = MyOps()        # 换掉算子表
```

⚠️ 但如果新算子是**多输出**的，还必须覆盖 `convert()`——因为输出注册逻辑在那里。上游化是更好的选择。

### 上游化检查清单

1. 在 `ONNXOperations` 中实现，签名保持 `(*args, attribute=None)`；
2. 加 Google 风格 docstring，附 [ONNX 算子文档](https://github.com/onnx/onnx/blob/main/docs/Operators.md) 链接；
3. 涉及形状变化时用 `_to_casadi_shape`，**不要**直接 `reshape`（会撞上 CasADi 的二维断言）；
4. 更新类 docstring 里的算子清单表；
5. 涉及形状变化时用 `_reduce_to_2d` 拿到目标二维形状，**注意存活维度的位置**（行向量 vs 列向量）；
6. 涉及元素重排（`Reshape`/`Flatten`/`Transpose`）时，记住 **ONNX 是行主序、CasADi 是列主序**；
7. 在 [`testing/test_onnx.py`](../testing/test_onnx.py) 补测试：既要**单元测**算子本身，也要**图测**（用 `onnx.helper` 手搭最小图，不依赖 torch）；
8. 跑全量测试：`cd testing && python -m unittest`（当前 **256** 个用例，约 1–3 分钟）。

## 七、性能代价与规模控制

同为 `n_horizon` 量级下的实测单步耗时：

| 代理模型 | 状态数 `n_x` | `opt_x` | 单步耗时 |
|---|---|---|---|
| FFN（3→32→32→2） | 2 | 小 | **19.5 ms**（最慢 48 ms） |
| LSTM（`n_hid=16`） | 33 | 543 | **287 ms**（最慢 411 ms） |

约 **15~21 倍**开销。原因：`h` 和 `c` 各 `n_hid` 维都要在**每个时域步**成为优化变量，且每步都要展开完整的四门计算图。

**控制手段（按性价比排序）：**

1. **减小 `n_hid`**。状态数是 `n_obs + 2·n_hid`，对 `opt_x` 线性、对 IPOPT 稀疏分解超线性。`n_hid` 从 16 降到 4，`opt_x` 从 543 降到 59（实测）。
2. **必须 `'discrete'`**，理由见 § 一。
3. `mpc.settings.set_linear_solver('MA27')` —— LSTM 模型的 KKT 稠密度高于机理模型，收益更明显。
4. `n_horizon` 够用就好。先用 `mpc.prepare_nlp()` 后打印 `mpc.opt_x_num.cat.shape` 评估。
5. 给 `h`/`c` 设**宽松但有限**的界（示例用 `±10` / `±30`）。不设界会让 IPOPT 缩放变差；设太紧会让递推不可行。
6. 若目标是"部署时够快"而非"在线优化"，考虑改用 [近似 MPC](05-进阶功能.md#四神经网络-mpc)。

## 八、踩坑清单

| # | 坑 | 症状 | 正确做法 |
|---|---|---|---|
| 1 | **导出序列 `LSTM` 而非 `LSTMCell`** | 图变成 24 节点 + 三维 `LSTM` 算子 | 永远导出 Cell |
| 2 | **门序搞混** | 结果全错但不报错 | PyTorch `weight_ih` 行块序是 **`i,f,g,o`**；ONNX `LSTM` 算子规范是 **`i,o,f,c`**。从 ONNX 图读权重要重排 |
| 3 | **`torch.onnx.export` 默认走 dynamo** | 产出未实现的算子 | 显式 `dynamo=False` |
| 4 | **`ca.vertsplit(v, n)` 的 `n` 是每块行数，不是块数** | `(8,1)` 传 4 得到 **2** 块，报 `too many values to unpack (expected 4)` | 用显式切片 `gates[0:H]`, `gates[H:2*H]`, ... |
| 5 | **行/列向量约定不一致** | 形状错误或结果转置 | ONNX/torch 用 `(1,N)`，do-mpc 用 `(N,1)`。边界转置 + `ca.substitute` 换符号 |
| 6 | **CasADi ≥3.8：`setup()` 之后建不了 `ca.Function`** | `variables [...] are free` | 验证用 Function 必须在 `setup()` **之前**建；之后一律用 `model._rhs_fun` |
| 7 | **归一化没折进符号表达式** | MPC 优化的是错的动力学 | `(x-mu)/sd` 与输出反归一化都要写成 CasADi 表达式的一部分 |
| 8 | **不归一化训练** | loss 看着小，实际废掉 | 实测：原始值训练相对误差 **53%**、稳态映射**符号都反了**；标准化后 **0.6%**。详见 [05 § 四](05-进阶功能.md#四神经网络近似-mpc) |
| 9 | **`model.n_x` 在 `setup()` 前不存在** | `AttributeError: 'Model' object has no attribute 'n_x'` | `n_x`/`n_u`/`n_z`/... 是 `setup()` 内部（`_model.py` 第 1041 行起）才赋值的 |
| 10 | **`Data` 幂索引里塞时间轴** | `Error occured in struct context with powerIndex (slice(None,None,None), 'p')` | 幂索引只索引**变量结构**，时间恒为返回数组第 0 轴：`data['_x','p'][-1]` |
| 11 | **`x.reshape(a, b)` 方法形式** | `DM.reshape() takes 2 positional arguments but 3 were given` | 用元组：`x.reshape((a, b))` |
| 12 | **numpy 广播** | `(2,1) - mu` 其中 `mu.shape==(2,)` → `(2,2)`；`np.random.uniform(LB,UB,size=(2,1))` 直接报广播错 | `mu.reshape(2,1)`；用 `.reshape(2,1)` 而非 `size=(2,1)` |
| 13 | **float32 / float64 混用** | `mat1 and mat2 must have the same dtype, but got Double and Float` | torch 权重是 float32，喂进去的 numpy 必须 `.astype(np.float32)` |
| 14 | **激活函数不可微** | IPOPT 收敛困难 | 用 `tanh`；`Relu` 实现为 `casadi.fmax(0,x)`，0 处导数不连续。**训练时就要选好** |
| 15 | **行主序 vs 列主序** | `Reshape` 结果元素顺序被打乱，**不报错** | ONNX/numpy 是行主序，CasADi 是列主序。库内已修正；自己写转换代码时用 `ca.vec(ca.transpose(x))` 取行主序展平，再用 `ca.transpose(ca.reshape(flat,(cols,rows)))` 重建 |
| 16 | **`Slice` 的 opset 差异** | `IndexError: list index out of range` | opset ≤ 9 用 attribute，opset ≥ 10 用 input。现代导出器一律是后者 |
| 17 | **`onnx.checker` 要求 initializer 先声明** | `Nodes in a graph must be topologically sorted, however input 'X' of node ...` | 手搭测试图时，initializer 必须传给 `make_graph(..., initializer=[...])`，不能事后 `extend` |
| 18 | **`Concat` 的 `axis` 是必填属性** | 手搭图时 `Required attribute 'axis' is missing` | 库端已做容错（缺省按 0），但 `onnx.checker` 仍会拒绝；测试此类容错需 `check=False` |
| 19 | **CasADi 不做 numpy 式广播** | `Dimension mismatch for (x-y), x is 2x5, while y is 1x5` | `(R,C)` 与 `(1,C)` 不能直接运算（与 `(R,1)` 可以）。逐通道参数必须 `casadi.repmat(row, R, 1)` 显式平铺 |
| 20 | **`Flatten`/`Reshape` 的主序** | 结果元素顺序被打乱，**不报错** | ONNX 是行主序、CasADi 是列主序。库内已用 `vec(transpose(x))` + `transpose(reshape(flat,(cols,rows)))` 修正；自己写时照抄 |
| 21 | **`onnx.checker` 要求 initializer 先声明** | `Nodes in a graph must be topologically sorted, however input 'X' of node ...` | 手搭测试图时 initializer 必须传给 `make_graph(..., initializer=[...])`，不能事后 `extend` |
| 22 | **`torch.onnx.export` 的 `output_path` 是必需位置参数** | 想在内存中导出时报 `AttributeError: 'NoneType' object has no attribute 'write'` | 传 `io.BytesIO()` 作为目标，再用 `onnx.load_model_from_string(buf.getvalue())` 读回 |
| 23 | **torch 层与 do-mpc 的向量方向** | `mat1 and mat2 shapes cannot be multiplied (3x1 and 3x16)` | torch 模块吃**行向量** `(1,n)`，do-mpc 变量是**列向量** `(n,1)`。喂 torch 前要 `.T` |
| 24 | **float64 比对只用 `rtol`** | `Mismatched elements: 1/10, Max absolute difference 5.0e-14` | 个别元素接近 0 时纯相对容差无意义，`assert_allclose` 必须同时给 `atol` |
| 25 | **numpy 比对两侧形状不一致** | 偏差报成 `1.82`，实际转换精度是 `8e-08` | `(n,1)` 与 `(n,)` 相减会**广播成 n×n 全对比较**。比之前必须两侧 `.ravel()`。我在 `test_graphics` 和 `test_ann_to_model` 各撞了一次 |
| 26 | **MPC 与 Simulator 的参数模板形状不对称** | `Error occured in struct context with powerIndex ('theta',)` | MPC 的模板多一个前导维（场景 / 时域），只能用 `t['_p', :, 'theta']`；Simulator/MHE/EKF 是扁平的，只能用 `t['theta']`。用 `_template_index_form()` 按结构 labels 检测 |
| 27 | **CasADi struct setter 不广播** | `Rhs out of range. Got list index 2 but rhs list is only of length 2` | 给跨 3 场景 × 2 参数的范围赋一个长度 2 的列表会失败。必须逐个索引填充（见 `_assign_constant()`） |
| 28 | **`ONNX ReduceMean` 的 `axes` 在 opset 18 才从属性变输入** | 手搭图时 `Node with schema(::ReduceMean:13) has input size 2 not in range [min=1, max=1]` | opset ≤17 用 `axes=[...]` 属性，opset ≥18 用输入。库端两者都支持 |
| 29 | **正数 `axis` 在 rank 被降维后指向错误维度** | `Unsqueeze`→`ReduceMean(axis=1)` 静默给出 `[1.0, 4.0]` 而非 `[1.5, 2.5, 3.5]` | 已用 `onnx.shape_inference` + `_resolve_axis()` 彻底修复（§ 9.6）。自己写算子时务必走 `_resolve_axis`，不要直接 `axis % 2` |

## 九、通用性边界（实测）

**问题**：换一个 ANN，是否只改模型就能跑通整条链路？
**答案**：**架构层面通用，语义层面必须声明，三维层面有硬边界。**

### 9.1 端到端通用性：11/11 架构

用同一个 `ann_to_dompc_model` 构建器 + 各自的声明式 spec，**构建器代码一行未改**：

```
architecture       nodes  n_x  n_u   opt_x
--------------------------------------------------
FFN tanh               5    2    2      26
FFN sigmoid            5    2    2      26
FFN elu                5    2    2      26
FFN relu               5    2    2      26
FFN deep x6           13    2    2      26
FFN wide 256           5    2    2      26
Linear only            1    2    2      26
Residual/skip          6    2    2      26
LSTMCell plant        15   10    1      76
GRUCell plant         17    6    1      48
Stacked LSTM x2       50   18    1     132
--------------------------------------------------
end-to-end do-mpc pipeline succeeded for 11 / 11
```

从 1 节点的纯线性到 **50 节点的双层堆叠 LSTM**，全部跑通 `Model → MPC.setup → Simulator → 闭环`。

### 9.2 算子覆盖：20 种常见 torch 层（补齐前快照，最新数据见 § 9.7）

| 状态 | 层 | 实测精度 |
|---|---|---|
| ✅ **18 种可转换** | `Linear` `Tanh` `Sigmoid` `ReLU` `ELU` `LeakyReLU` `GELU` `SiLU` `Softplus` `Hardtanh` `Softmax` `Dropout(eval)` `BatchNorm1d` `LayerNorm` `Flatten` `LSTMCell` `GRUCell` `RNNCell` | `3.3e-08` ~ `2.9e-07`（float32 底噪） |
| ❌ **2 种被阻断** | `Conv1d`、`LSTM`（序列版） | — |

两种被阻断的都是**同一个根因**：需要真三维。

| 层 | 缺失算子 | 报错 |
|---|---|---|
| `Conv1d` | `Conv` | `Operation 'Conv' not implemented` |
| `LSTM`（序列） | `Expand` `Gather` `LSTM` | `Transpose with perm=[1, 0, 2] is not supported: CasADi is strictly two-dimensional` |
| `MultiheadAttention` | `ReduceMean` `Softmax` + 三维 `Transpose` | 同上（36 节点） |

> ✅ 序列 `LSTM` **可以绕过**：导出 `LSTMCell` 即可（14 节点，全部算子已支持）。
> ❌ `Conv` 无法绕过，除非训练时改用全连接/Toeplitz 等价结构。

### 9.3 必须逐模型声明的四项（原理上无法自动化）

这四项是**语义信息，不在权重里**，任何工具都推断不出来：

| # | 声明什么 | spec 字段 | 为什么无法自动推断 |
|---|---|---|---|
| 1 | **接线**：每个 ONNX 输入 ← 哪些 do-mpc 变量、拼接顺序 | `wiring` | 网络只看到"一个 3 维输入"，不知道前 2 维是状态、后 1 维是控制量 |
| 2 | **状态划分**：哪些张量必须提升为 `_x` | `x_spec` | LSTM 的 `h`/`c` 在 ONNX 图里只是普通输入，只有你知道它们是**需要跨时刻保持的记忆** |
| 3 | **输出指派**：哪个图输出驱动哪个状态 | `outputs` | 图输出是无名张量 |
| 4 | **归一化统计量**：`mu`/`sd` 必须折进表达式 | ⚠️ `ann_to_dompc_model` **不代管**此项 —— 需你在 torch 模块内部（或导出前）把归一化层做进网络，或走手工路径显式写入 | 训练时的预处理不属于网络权重，工具无从得知 |

**所以"通用"的正确形态是：把这四项做成声明式 spec，构建器本身通用。** 换模型 = 改 spec，不改代码。

> ✅ 前三项现已全部支持（`p_spec`/`tvp_spec`/`z_spec`/`algebraic`/`measurements`，见 § 9.5）。第四项（归一化）仍是调用方的责任——这是原理性边界，不是实现缺陷。
第四项（归一化）目前落在调用方，是这套 API 唯一的遗留手工环节 —— 因为它取决于你训练时怎么预处理的，工具无从推断。

### 9.4 架构层面的额外知识点

| 架构 | 可行性 | 做法 |
|---|---|---|
| **RNN / GRU / LSTM** | ✅ 已实测 | 导出 **Cell**，隐状态入 `_x` |
| **多层 / 堆叠 LSTM** | ✅ 已实测（50 节点） | 每层 `(h,c)` 拼进同一个 `_x` 向量，`wiring` 里拆开 |
| **残差 / skip connection** | ✅ 已实测 | 就是 `Add`，无需特殊处理 |
| **BatchNorm / LayerNorm** | ✅ 已实测 | `BatchNormalization` 需 **eval 模式**导出（training_mode 会明确报错） |
| **GELU** | ✅ 已实测 | 依赖 `Erf` + `Div`，`casadi.erf` 本来就存在 |
| **双向 LSTM** | ⚠️ 需重新设计 | MPC 是因果滚动，反向层只能看历史 |
| **Transformer / Attention** | ⚠️ 较难 | 需自己按 2-D 重写 attention；`Softmax`/`ReduceMean` 已可用 |
| **Conv / 池化** | ❌ | 三维滑窗，超出 CasADi 表达能力 |

⚠️ **门序 (gate order)** 是唯一"换个来源就变"的知识点：PyTorch `weight_ih`/`weight_hh` 行块顺序是 **`i, f, g, o`**；ONNX 融合 `LSTM` 算子规范是 **`i, o, f, c`**。手工翻译用前者，走 ONNX 路径时 `Split` 已按图携带的顺序拆好。**搞错不会报错，只会得到完全错误的动力学。**

### 9.5 通用性审计与后续补齐 ✅

上一版审计列出 7 项不通用之处。**其中 6 项已实现，1 项确认为原理性边界。**

| # | 原限制 | 状态 | 实现方式 |
|---|---|---|---|
| 1 | `_p` / `_tvp` 无法接线 | ✅ **已补齐** | `p_spec` / `tvp_spec` 参数 + `wiring` 支持 `'p'`/`'tvp'` kind + `set_constant_parameters` / `set_constant_tvp` 两个辅助函数 |
| 2 | `_z` / DAE 无法构建 | ✅ **已补齐** | `z_spec` + `algebraic` 参数 → `set_alg`；`wiring` 支持 `'z'` kind（隐式 DAE `0=g(x,u,z)` 必需） |
| 3 | 无 `set_meas` 钩子 | ✅ **已补齐** | `measurements` 参数；来源可以是图输出（含切片）或 `('x', name)` / `('z', name)` 引用 |
| 4 | 输出→状态严格 1:1 且等宽 | ✅ **已补齐** | `resolve_output` + `(key, slice)` 形式；键还可以是**任意中间节点名**，不限于图输出 |
| 5 | 归一化统计量不代管 | ⚠️ **原理性边界** | 取决于训练时的预处理，权重里没有该信息，工具无从推断。需把归一化做进 torch 模块，或走手工路径 |
| 6 | `model_type='continuous'` 语义无法校验 | ✅ **已加警告** | `warnings.warn` 说明 discrete/continuous 的区别与正交配置的规模代价 |
| 7 | 轴语义在降维后有歧义 | ✅ **已彻底修复** | `onnx.shape_inference` 追踪每个值的 ONNX rank，见 § 9.6 |

#### 补齐后的完整 API

```python
model, converter = do_mpc.sysid.ann_to_dompc_model(
    source,               # torch.nn.Module / .onnx 路径 / onnx.ModelProto
    x_spec  = [('x', 2), ('h', 8), ('c', 8)],   # 状态（含循环网络的隐状态）
    u_spec  = [('u', 1)],                       # 输入
    p_spec  = [('theta', 2)],                   # ★ 参数：可被 MHE 估计、可作鲁棒不确定量
    tvp_spec= [('ref', 1)],                     # ★ 时变参数：参考轨迹 / 预报
    z_spec  = [('alg', 2)],                     # ★ 代数状态 → DAE
    wiring  = [('z', [('x','x'), ('u','u'), ('p','theta'), ('tvp','ref'), ('z','alg')])],
    outputs = [((0, slice(0, 2)), 'x')],        # ★ 支持切片：一个宽输出驱动多个状态
    algebraic   = [((0, slice(2, 4)), 'alg')],  # ★ 0 = g(x,u,z)
    measurements= [((0, slice(4, 5)), 'y', True)],  # ★ set_meas(name, expr, meas_noise)
    sample_args = (...), input_names = ['z'],
    model_type='discrete', symvar_type='SX', verbose=False)
```

配套的三个新导出：

| 名称 | 作用 |
|---|---|
| `resolve_output(converter, key)` | 把 `int` / `str` / `(key, slice)` 解析成 `(name, expression)`；键可以是图输出**或任意中间节点**；切片越界给出清晰报错 |
| `set_constant_parameters(optimizer, n_combinations=1, **values)` | 注册一个恒定 `p_fun`。**自动处理 MPC 与 Simulator/MHE/EKF 的模板形状差异**（见下） |
| `set_constant_tvp(optimizer, **values)` | 注册一个恒定 `tvp_fun`，把同一个值填满整个预测时域（即恒定设定值） |

> ⚠️ **模板形状不对称**，这是补 `_p`/`_tvp` 时踩到的最大的坑：
>
> | 类 | `get_p_template` / `get_tvp_template` 的可用索引 |
> |---|---|
> | **MPC** | `t['_p', :, 'theta']`、`t['_tvp', :, 'ref']` —— **多一个前导维**（场景索引 / 时域索引）。`t['theta']` 会抛 `Error occured in struct context with powerIndex ('theta',)` |
> | **Simulator / MHE / EKF** | `t['theta']`、`t['ref']` —— 扁平。反过来用 MPC 的形式会失败 |
>
> `_template_index_form()` 通过**结构 labels** 检测属于哪一种，因此两个辅助函数对任何 optimizer 都适用。另外 CasADi 的 struct setter **不做广播**：给跨 3 个场景 × 2 个参数的范围赋一个长度 2 的列表会报 `Rhs out of range`，所以 `_assign_constant()` 逐个索引填充。

### 9.6 ONNX rank 追踪：轴歧义已彻底修复 ✅

§ 9.5 表中的 #7 原先是"文档化 + 测试钉住"，现已**真正修复**。

**机制**：

1. `ONNXConversion.__init__` 调用 `onnx.shape_inference.infer_shapes` 建立 `self.ranks`——覆盖图输入、**中间值** (`value_info`)、输出与 initializer；
2. `convert()` 在派发每个节点前，把首输入/首输出的 rank 偏移写到算子实例上：`operations._axis_offset_in` / `_axis_offset_out`；
3. 所有带 `axis` 的算子改用 `_resolve_axis(axis, which)` 换算：

```
onnx_rank   = 2 + offset
normalized  = axis % onnx_rank          # ONNX 的负轴约定
casadi_axis = normalized - offset
if casadi_axis < 0: raise               # 指向被丢弃的前导维
```

`Unsqueeze` 的轴指的是**结果**张量，所以用 `_axis_offset_out`；`Squeeze` 指的是输入，用 `_axis_offset_in`。

**实测对照**：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| `Unsqueeze(axis=0)` → `ReduceMean(axis=1)` | `[1.0, 4.0]` 形状 `(2,1)` ❌ | `[1.5, 2.5, 3.5]` 形状 `(1,3)` ✅ 与 ONNX 一致 |
| 同上但 `axis=-1` | 正确（负轴从末尾数） | 仍然正确 ✅ |
| `Transpose(perm=[0,2,1])` on `[1,B,C]` | 抛"三维不支持" | ✅ 正确给出 `val.T`（前导单元素维留在原位是合法的） |
| `Transpose(perm=[2,1,0])` | 抛错 | 仍然抛错 ✅（它把被丢弃的维移进了存活的二维） |
| 纯 rank-2 图（offset=0） | — | **行为完全不变**（`axis % 2`），87 个既有测试无回归 |
| `Softmax(axis=2)` on rank-2 | 静默取模成 axis 0 | ✅ 明确报 `axis 2 is out of range for a rank-2 tensor` |
| `LayerNormalization(axis=1)` on `[1,B,C]` | 静默返回形状 `(2,6)` 的错误结果 ❌ | ✅ 按 ONNX 组语义对**整个矩阵**归一化，形状 `(2,3)`，与手算参考差 `1.5e-07` |
| `LayerNormalization(axis=0)` on rank-2（即 `torch.nn.LayerNorm([rows, cols])`） | 静默按行归一化 ❌（**与 rank 追踪无关的既有缺陷**） | ✅ 同样覆盖两个轴，与 torch 差 `7.4e-08` |

**降级安全**：`_collect_ranks` 全程 `try/except`；形状推断失败或名字缺失时 offset 取 0，退回到原有的 rank-2 行为。

**审计中发现并一并修掉的连带缺陷（`LayerNormalization` 的组语义）**：ONNX 规定 `normalized_axes = [axis, ..., rank-1]`——归一化组**一直延伸到最后一维**。因此只要 `_resolve_axis` 把轴映射到 CasADi 的**行**（`casadi_axis == 0`），该组就同时覆盖 CasADi 的两个轴，统计量必须对整个矩阵求。原实现只做单轴 `sum1` 归约：

* 对 `axis=1` 的 rank-3 张量，返回形状 `(2,6)` 的错误结果；
* 对 `axis=0` 的**纯 rank-2** 图也算错——而 `torch.nn.LayerNorm([rows, cols])` 正是这样导出的（`axis=-2`）。这一条与 rank 追踪无关，是本次审计顺带暴露出来的既有缺陷。

现由 `_layer_norm_over_all_elements` 处理。它不复用 `_as_row`，因为 CasADi 是**列主序**而 ONNX 是**行主序**，把逐元素的 `scale`/`bias` 先 `ravel` 会打乱对齐；新增的 `_as_matrix(value, rows, cols)` 保持 `(rows, cols)` 布局。求和与元素顺序无关，所以这里不受主序差异影响。`axis=-1`（绝大多数导出器的情形）仍走原来的单轴路径，**行为完全不变**。

**回归保护**：`testing/test_onnx.py::TestRankTracking`（**13** 个用例）覆盖 ranks 收集、正轴重映射、负轴不变、`Softmax`/`Transpose` 各 perm、rank-2 不变性、越界轴报错、缺 rank 信息时的降级、`Unsqueeze`+`Squeeze` 往返、`LayerNormalization` 跨双轴组语义（rank-3 与 rank-2 各一）；`TestExtendedOperators` 另有 5 个用例钉住"整矩阵归一化 ≠ 按行归一化"、`axis=-2 == axis=0`、`axis=-1` 仍是单轴、以及 `_as_matrix` 的行列对齐。

### 9.7 补齐后的算子覆盖

| 状态 | 层 |
|---|---|
| ✅ **22 / 24 可转换** | `Linear` `Tanh` `Sigmoid` `ReLU` `ELU` `LeakyReLU` `GELU` `SiLU` `Softplus` `Hardtanh` `Softmax` `Dropout(eval)` `BatchNorm1d` `LayerNorm` `LayerNorm([rows, cols])`（全维归一化） `Flatten` `deep×6` `wide 256` `Residual` `LSTMCell` `GRUCell` `RNNCell` |
| ❌ **2 / 24 被阻断** | `Conv1d`（需三维滑窗）、`LSTM` 序列版（融合算子作用于三维张量） |

精度全部落在 `3.5e-08 ~ 3.8e-07`（float32 底噪）。两个被阻断项现在都给出**指向根因**的错误信息，而不是含糊的 `IndexError`。`LogSoftmax` 尚未实现，会明确报 `Operation 'LogSoftmax' not implemented`。


### 9.8 一句话总结

> 找到架构的**递推状态** → 放进 `_x` → 把**单步更新**交给 `ann_to_dompc_model` 的声明式 spec。
> 这三步走通，do-mpc 其余部分（离散化、约束、IPOPT、MHE、鲁棒 MPC、绘图）全部自动可用。
