## 一、时变参数 `_tvp` 到底怎么用

这是官方 [`FAQ.rst`](../documentation/source/FAQ.rst) 的头号话题，也是最容易搞混的地方。

### 什么时候需要 `_tvp`？

MPC / MHE 考虑的是一段**有限的未来（控制）或过去（估计）轨迹**，这段轨迹每步都在移动。当满足下面任一条件时，就需要 `_tvp`：

1. 模型受**外部影响**，且该影响在时域内逐时刻变化（例如天气预报、上游来料）；
2. **代价函数**中含有逐时刻变化的量（例如**参考轨迹 / 设定值**）。

共同点：这些量是**先验已知的**，且**在时域内不是常数**。

### 与 `_p` 的区别（再次强调）

| | `_p` 参数 | `_tvp` 时变参数 |
|---|---|---|
| 时域内 | 恒定（一个值贯穿全程） | 逐时刻变化（一整条序列） |
| 先验已知？ | 通常未知 | **必须已知** |
| 能被 MHE 估计？ | ✅ | ❌ |
| 能作为鲁棒 MPC 的不确定量？ | ✅ | ❌ |
| 典型用途 | 反应速率常数、摩擦系数、惯量 | 设定值轨迹、天气预报、时变权重矩阵 |
| 通常出现在 | 模型方程 | 模型方程 **和** 代价函数 |

### 完整示例：温度跟踪控制

**① 在模型中声明**

```python
model = do_mpc.model.Model('continuous')

temperature          = model.set_variable('_x',   'temperature')
temperature_set_point = model.set_variable('_tvp', 'temperature_set_point')  # 设定值
temperature_external  = model.set_variable('_tvp', 'temperature_external')   # 外部扰动

model.set_rhs('temperature', alpha*(temperature_external - temperature))
model.setup()
```

**② 在 MPC 中用于代价函数**

```python
mpc = do_mpc.controller.MPC(model)
mpc.settings.n_horizon = 20
mpc.settings.t_step    = 60

# ★ 用 model.x / model.tvp 取符号 —— 不要在 mpc 配置文件里依赖 python 局部变量
lterm = (model.x['temperature'] - model.tvp['temperature_set_point'])**2
mpc.set_objective(lterm=lterm, mterm=lterm)
```

> 💡 **为什么要用 `model.x['...']` 而不是直接用局部变量 `temperature`？**
> 因为约定俗成会把 model / mpc / simulator 拆到不同文件（四文件模板）。在 `template_mpc.py` 里，`temperature` 这个 Python 变量根本不存在，只能从 `model` 对象上取符号。

得到的代价函数：$J = \sum_{k=0}^{N+1}(T_k - T_{k,\text{set}})^2$

**③ 提供数值 —— MPC（二维模板）**

```python
tvp_template = mpc.get_tvp_template()      # 形状 (n_tvp, n_horizon+1)

def tvp_fun(t_now):
    # 索引方式 1：按名字 + 时刻
    for k in range(mpc.settings.n_horizon + 1):
        tvp_template['temperature_set_point', k] = 从某处取第 k 步的设定值
    # 索引方式 2：整段切片赋值（更高效）
    tvp_template['temperature_external', :] = 未来 n_horizon+1 步的预报值
    return tvp_template

mpc.set_tvp_fun(tvp_fun)
```

`tvp_fun` 会在**每次 `mpc.make_step()` 内部被调用**，所以里面可以做任何事：读 numpy 数组、查数据库、按 `t_now` 计算、调用外部预报服务……

**④ 提供数值 —— Simulator（一维模板）**

```python
simulator = do_mpc.simulator.Simulator(model)
simulator.settings.t_step = 60

tvp_template = simulator.get_tvp_template()   # 形状 (n_tvp,) —— 只要当前值

def tvp_fun(t_now):
    tvp_template['temperature_external'] = ...
    return tvp_template

simulator.set_tvp_fun(tvp_fun)
```

> ⚠️ **两个关键区别：**
> 1. **Simulator 的模板是一维的**（只需当前时刻的值），MPC/MHE 的是二维的（需要整条序列）。索引方式因此简单得多。
> 2. **没有显式赋值的 tvp 默认为 `0`**。所以只为控制器引入的 `temperature_set_point`，在仿真器里**不必**设置（仿真器不需要知道你的控制目标）。
>
> 💡 **从仿真器视角看，`_p` 和 `_tvp` 没有区别** —— 都只是"当前时刻的一个数"。区别只在 MPC / MHE 中才有意义。

**⑤ MHE 中同理**，配置方式与 MPC 完全一致（二维模板 + `set_tvp_fun`）。

## 二、可行性问题

MPC / MHE 最常见的运行时问题：**求解器无法满足约束**。IPOPT 会输出 `INFEASIBLE_PROBLEM_DETECTED` 或返回一个"最优"但明显违反约束的解。

### 诊断步骤 1：初值可行吗？

MPC 的问题**在初值不可行时必然不可行**。闭环运行中，状态预测与真实演化会有偏差，某一步的真实状态可能落到约束边界之外。

```python
# 检查当前 x0 是否满足 bounds
print(mpc.x0.cat)
print(mpc.bounds['lower','_x','C_a'], mpc.bounds['upper','_x','C_a'])
```

### 诊断步骤 2：哪些约束被违反了？

官方 FAQ 给出的方法 —— 取出（不可行的）"最优解"与边界比对：

```python
lb_bound_violation = mpc.opt_x_num.cat <= mpc.lb_opt_x      # 低于下界
ub_bound_violation = mpc.opt_x_num.cat >= mpc.ub_opt_x      # 高于上界

opt_labels   = mpc.opt_x.labels()                            # 所有优化变量的名字
labels_lb_viol = np.array(opt_labels)[np.where(lb_bound_violation)[0]]
labels_ub_viol = np.array(opt_labels)[np.where(ub_bound_violation)[0]]

print(labels_lb_viol)      # ← 这些变量出了问题
print(labels_ub_viol)
```

标签形如 `_x_12_C_a`，能直接定位到**哪个变量、哪个时刻**。

> ⚠️ 官方 FAQ 中这段代码有个笔误：`np.where(lb_viol)` 应为 `np.where(lb_bound_violation)`，且 `labels_ub_viol` 那行误用了 `lb_viol`。上面是修正版。

### 诊断步骤 3：边界本身矛盾吗？

`setup()` 时会自动检查，报错消息是：

```
Your bounds are inconsistent. For {...} you have lower bound > upper bound.
```

### 解决方案 A：软约束

某些控制问题（尤其是**经济型目标**）会让轨迹紧贴约束运行。不确定性或模型误差就会把它推出可行域，导致"不可行 → 无意义解"。

```python
mpc.set_nl_cons('T_R', model.x['T_R'], ub=140,
                soft_constraint=True,          # ★ 引入松弛变量 ε
                penalty_term_cons=1e2,         # ★ 惩罚权重，建议取大值
                maximum_violation=np.inf)      # ε 的上界
```

数学形式：

$$m(x,u,z,p_{tv},p) - \epsilon \le m_{ub},\qquad 0 \le \epsilon \le \epsilon_{max}$$

代价中追加 $\text{penalty}\cdot\|\epsilon\|^2$。这样**有限的违反是被容忍的**，不会导致不可行。

配套设置：

```python
mpc.settings.nl_cons_single_slack = True   # 整个时域只用一个 ε（问题更小）
```

MPC 与 MHE **都支持**软约束。

### 解决方案 B：终端约束放松

如果用了 `use_terminal_bounds=True`，终端约束常常是不可行的元凶。先关掉试试：

```python
mpc.settings.use_terminal_bounds = False
```

### 解决方案 C：检查初值

```python
mpc.x0 = x0            # 必须与真实状态一致
mpc.u0 = u_prev        # 若用了 set_rterm，u_prev 会进入问题
mpc.set_initial_guess()  # ★ 用 x0/u0/z0 填满整个时域
```

若 `set_initial_guess()` 给的初值太差，可以直接操纵 `opt_x_num`：

```python
mpc.opt_x_num['_x', :, 'C_a'] = 0.5     # 给整条 C_a 轨迹一个合理初值
```

### 解决方案 D：改善数值条件

见 [性能优化清单](#五性能优化清单)。**很多"不可行"其实是"数值上求解失败"**。

## 三、静默 IPOPT

IPOPT 是 MPC 与 MHE 的默认求解器。

> 📌 **官方建议：一般情况下应该保留求解器输出**，用于检查可行性问题。只在确认问题稳定后才静默。

```python
mpc.settings.supress_ipopt_output()      # ⚠️ 拼写是 supress（源码 typo），不是 suppress
mhe.settings.supress_ipopt_output()
```

等价于：

```python
mpc.settings.nlpsol_opts.update({'ipopt.print_level': 0, 'ipopt.sb': 'yes', 'print_time': 0})
```

> 示例代码里通常做成开关：
> ```python
> def template_mpc(model, silence_solver=False):
>     ...
>     if silence_solver:
>         mpc.settings.supress_ipopt_output()
> ```
> 测试代码全部用 `silence_solver=True` 调用。

### 4.1 建模阶段（`Model`）

| 错误消息 | 原因 | 解决 |
|---|---|---|
| `model_type must be string, you have: ...` | `Model()` 第一个参数不是字符串 | 传 `'continuous'` 或 `'discrete'` |
| `model_type must be either discrete or continuous, you have: ...` | 拼写错误 | 只能是这两个值之一 |
| `symvar_type must be either SX or MX, you have: ...` | 第二个参数错误 | 传 `'SX'`（默认）或 `'MX'` |
| `The variable name X for type _x already exists.` | 重复声明同名变量 | 改名 |
| `shape must be tuple or int, you have: ...` | `set_variable(shape=...)` 类型错 | 传 `int` 或 `tuple`，如 `(2,1)` |
| `integer must be boolean, you have: ...` | `input_type_integer` 不是 bool | 传 `True`/`False` |
| **`Only inputs can be declared as integer variables, you tried to declare X`** | 想给状态/参数设整数类型 | ⚠️ **只有 `_u` 支持整数**（MINLP） |
| `Trying to set non-existing variable var_type: X` | `set_variable` 的 `var_type` 非法 | 合法值：`_x`, `_u`, `_z`, `_p`, `_tvp` |
| **`Definition of right hand side (rhs) is incomplete. Missing: [...]. Use: set_rhs to define expressions.`** | 有状态没调 `set_rhs` | ★ **每个 `_x` 都必须调一次 `set_rhs`** |
| `var_name must refer to the previously defined states ([...]). You have: X` | `set_rhs('X', ...)` 的 `X` 没声明过 | 先 `set_variable('_x','X')` |
| `expr must be a casadi SX or MX type, you have: ...` | 传了 numpy / float | 表达式必须由 CasADi 符号构成 |
| `expr_name must be str, you have: ...` | 名字不是字符串 | — |
| `Cannot call .set_variable after setup.` | `model.setup()` 后又改模型 | **`setup()` 是冻结点**，需重建模型 |
| `Cannot call .set_rhs after .setup.` | 同上 | 同上 |
| `Cannot call .set_expression after .setup()` | 同上 | 同上 |

| 错误消息 | 原因 | 解决 |
|---|---|---|

### 4.8 MPC 专属

| 错误消息 | 原因 | 解决 |
|---|---|---|
| **`Exception: You have not supplied a function to obtain the parameters defined in model. Use .set_p_fun() (low-level API) or .set_uncertainty_values() (high-level API) prior to setup.`** | 模型有 `_p` 但两个 API 都没用 | ★ `set_uncertainty_values(...)` 或 `set_p_fun(...)` |
| **`Exception: You have not supplied a function to obtain the time-varying parameters defined in model. Use .set_tvp_fun() prior to setup.`** | 模型有 `_tvp` 但没给 `tvp_fun` | ★ `get_tvp_template()` + `set_tvp_fun()` |

## 五、性能优化清单

按**性价比从高到低**排序：

### 1. 换 HSL MA27 线性求解器 ⭐⭐⭐⭐⭐

```python
mpc.settings.set_linear_solver('MA27')
```

IPOPT 的瓶颈是反复求解大规模稀疏对称不定线性系统。默认 MUMPS 换成 MA27 **通常有显著提速**。需要系统级安装 HSL，见 [快速开始 § 二](01-快速开始.md#二性能加速hsl-ma27-线性求解器可选但强烈推荐)。

### 2. 变量缩放 ⭐⭐⭐⭐⭐

```python
mpc.scaling['_x', 'T_R']   = 100
mpc.scaling['_u', 'Q_dot'] = 2000
```

**目标**：缩放后所有变量的典型值落在 `[0.1, 10]`。IPOPT 对量级极其敏感 —— 温度 `~130` 与浓度 `~0.5` 混在一起会严重拖慢收敛甚至导致失败。**这是最重要也最容易被忽略的一步。**

### 3. 关掉不必要的存储 ⭐⭐⭐⭐

```python
mpc.settings.store_full_solution  = False   # 除非要做预测动画
mpc.settings.store_lagr_multiplier = False  # 除非要做灵敏度/约束诊断
mpc.settings.store_solver_stats = ['success']   # 只留必要的
```

`store_full_solution=True` 会存下**整个时域所有场景**的完整解，内存开销随 `n_horizon × n_combinations` 线性增长。

### 4. 控制鲁棒 MPC 的规模 ⭐⭐⭐⭐

```python
mpc.settings.n_robust = 1        # 而不是 2 或 3（指数增长！）
mpc.settings.open_loop = False   # 除非规模实在太大
```

或用低层 API 打破笛卡尔积，把 `n_combinations` 从 $\prod m_i$ 降到 $\sum(m_i-1)+1$。详见 [进阶功能 § 一](05-进阶功能.md#规模估算与调优)。

### 5. 调整离散化 ⭐⭐⭐

```python
mpc.settings.collocation_deg = 2    # 降到 2（默认）甚至 1
mpc.settings.collocation_ni  = 1    # 需要精度时增加这个，而不是增加 deg
mpc.settings.cons_check_colloc_points    = False   # 盒式约束只在有限元边界检查
mpc.settings.nl_cons_check_colloc_points = False   # 默认已是 False
```

⚠️ 关掉 `cons_check_colloc_points` 意味着**约束可能在配置点之间被轻微违反**，需评估是否可接受。

### 6. 缩短时域 / 增大步长 ⭐⭐⭐

```python
mpc.settings.n_horizon = 20      # 够用就好
mpc.settings.t_step    = 0.1     # 增大步长直接减少变量数
```

总预测时长 = `n_horizon × t_step`，两者要一起考虑。

### 7. 提供好的初值 ⭐⭐⭐

```python
mpc.set_initial_guess()                       # 用 x0/u0/z0 填满时域
mpc.opt_x_num['_x', :, 'T_R'] = T_R_profile   # 更进一步：给整条轨迹一个物理合理的猜测
```

do-mpc 默认做**时域平移热启动**（上一步的解平移一格作为这一步的初值），配合 `ipopt.warm_start_init_point='yes'` 效果更好。

### 8. 选对符号类型 ⭐⭐

- 标量运算为主的模型 → `SX`（默认，通常更快）
- 含大矩阵乘法 → `MX`

### 9. 用近似 MPC 彻底摆脱在线优化 ⭐⭐

对毫秒级/嵌入式场景，训练神经网络替代在线求解。见 [进阶功能 § 四](05-进阶功能.md#四神经网络近似-mpc)。

### 10. 关闭求解器输出 ⭐

```python
mpc.settings.supress_ipopt_output()
```

大量控制台 I/O 在长时仿真中确实会拖慢速度（尤其在 Windows 上）。⚠️ 但**调试期请保留输出**。

### 测量性能

```python
from do_mpc.tools import Timer
timer = Timer()
for k in range(50):
    timer.tic(); u0 = mpc.make_step(x0); timer.toc()
timer.info()      # Average / worst case / best case
timer.hist()      # 直方图
```

## 六、Pickle 与序列化

### 6.1 什么能被 pickle？

| 对象 | 可否 pickle | 备注 |
|---|---|---|
| `Model`（SX，已 setup） | ✅ | 测试 `test_pickle_unpickle` 覆盖了这条路 |
| `Model`（**MX**） | ❌ | `Exception: Pickling of models using MX symvars is not supported.` |
| `Model`（**未 setup**） | ❌ | `Exception: Pickling of unsetup models is not supported.` |
| `Data` / `MPCData` | ✅ | `save_results` 存的就是这个 |
| `MPC` / `Simulator` / `MHE` 对象本身 | ⚠️ | `save_results` **只提取 `.data`**，不存整个对象 |

`Model.__getstate__` / `__setstate__` 会剔除不可序列化的 CasADi 对象，加载后需要重新 `setup()` 相关派生类。

### 6.2 CasADi 版本与 pickle 兼容性 ⚠️

这是 [`_casadi_compat.py`](../do_mpc/_casadi_compat.py) 存在的主要原因之一。

| 写入时的 CasADi | 读取时的 CasADi | 结果 |
|---|---|---|
| ≤ 3.7 | ≤ 3.7 | ✅ |
| ≤ 3.7 | ≥ 3.8 | ✅ **兼容层已处理**（注册了 `casadi.tools.structure3` 别名） |
| ≥ 3.8 | ≤ 3.7 | ❌ **不可恢复** —— CasADi 自身的 `Function` 二进制序列化有版本门禁，拒绝读取更新的文件 |

**建议**：团队内统一 CasADi 大版本，尤其是共享 `.pkl` 结果文件时。

### 6.3 存取接口

```python
# do-mpc 专用（自动只提取 .data，自动处理重名）
do_mpc.data.save_results([mpc, simulator, estimator], 'my_run',
                         result_path='./results/', overwrite=False)
res = do_mpc.data.load_results('./results/my_run.pkl')

# 通用
from do_mpc.tools import save_pickle, load_pickle
save_pickle('anything', some_object)      # 自动补 .pkl 后缀
obj = load_pickle('anything.pkl')
```

> ⚠️ `save_results(overwrite=False)` 时若文件已存在，会自动改名为 `001_my_run.pkl`、`002_my_run.pkl`…… **不会覆盖**。测试代码里都用 `overwrite=True`。
>
> ⚠️ `.gitignore` 中有 `examples/**/*.pkl`，所以示例目录里生成的结果文件**不会被提交**。但 `testing/results/*.pkl`（黄金结果）是**入库的**。

### 7.1 `ModuleNotFoundError: No module named 'packaging'` ⚠️

[`do_mpc/__init__.py`](../do_mpc/__init__.py) 的**第一行导入**就是：

from packaging import version

理论上 `packaging` 会作为 `setuptools`/`pip` 的传递依赖被装进来，但在**极简的干净虚拟环境**里可能缺失。解决：

```bash
pip install packaging
# 或干脆装完整版
pip install "do-mpc[full]"
```

## 八、常见建模陷阱

### 8.1 忘了给输入设边界

`bounds` 默认是 `±inf`。**忘记设界 = 优化器会给出物理上不可能的输入**（例如无限大的热流），而且不会报错。

```python
# ★ 每个 _u 都应该有界
mpc.bounds['lower', '_u', 'F']     = 5
mpc.bounds['upper', '_u', 'F']     = 100
mpc.bounds['lower', '_u', 'Q_dot'] = -8500
mpc.bounds['upper', '_u', 'Q_dot'] = 0
```

### 8.2 `mpc.settings.t_step` 与 `simulator.settings.t_step` 不一致

这会让"仿真时间"与"控制时间"错位，结果完全错误但**不报错**。两者应严格相等。

### 8.3 忘了 `set_initial_guess()`

```
MPC was not setup yet / opt_x_num 全为 0 → IPOPT 从平凡初值出发 → 收敛慢或不可行
```

```python
mpc.x0 = x0
simulator.x0 = x0
mpc.set_initial_guess()          # ★
simulator.set_initial_guess()    # ★（DAE 模型尤其重要，代数变量需要合理初值）
```

### 8.4 用 `set_expression` 与用普通 Python 变量的区别

```python
# ✅ 会被记录进 data，可绘图、可在别的文件里通过 model.aux['T_dif'] 访问
T_dif = model.set_expression('T_dif', T_R - T_K)

# ❌ 只在当前文件可见，不会被记录，无法绘图
K_1 = beta * K0_ab * exp(-E_A_ab/(T_R+273.15))
```

两者都是合法的 CasADi 表达式，都能用在 `set_rhs` 里。区别只在于**是否被 `Data` 记录**。想画图的量一定要用 `set_expression`。

### 8.5 `set_meas` 不调用 = 默认全状态可测

如果没调 `set_meas`，do-mpc 默认 $y = x$。这时用 `StateFeedback` 是合理的。
一旦调了 `set_meas`，就必须配一个真正的估计器（`EKF` / `MHE`），否则 `StateFeedback.make_step(y)` 返回的是**测量值而不是状态**，维度都可能对不上。

### 8.6 连续 DAE 忘了设 `integration_tool='idas'`

```python
# 模型含 _z 且 model_type='continuous' 时：
simulator.settings.integration_tool = 'idas'    # 默认是 'cvodes'，只支持 ODE
```

### 8.7 `mterm` 里引用了 `_u` 或 `_z`

终端代价在时域末端 $N+1$ 评估，那里**没有**控制输入和代数变量。源码会报：

```
Exception: mterm must be ... with respect to _x, _tvp, _p
```

### 8.8 `tvp_fun` / `p_fun` 返回了新对象而不是模板

```python
# ❌ 错误：返回了一个 numpy 数组
def tvp_fun(t_now):
    return np.array([...])

# ✅ 正确：返回 get_tvp_template() 拿到的那个结构体对象
tvp_template = mpc.get_tvp_template()
def tvp_fun(t_now):
    tvp_template['T_set', :] = ...
    return tvp_template
```

源码会用 `labels()` 比对结构，不匹配就报 `Incorrect output of tvp_fun`。

### 8.9 在多个示例间复制代码导致模块串味

不同示例目录下都有同名的 `template_model.py`。若在同一个 Python 进程/Jupyter 会话里连续 import，**后一次会拿到缓存的前一个模块**。

```python
from importlib import reload
import template_model
template_model = reload(template_model)      # 强制重载
```

这正是 `testing/*.py` 里 `setUp` 的做法。Jupyter 用户尤其要注意，必要时重启 kernel。

### 8.10 LQR + `linearize` 后忘记减去设定值

`linearize` 返回的是**增量形式**模型（$\Delta\dot x = A\Delta x + B\Delta u$，新增输入 `q` 代表 $\dot u$）。LQR 的解是绝对量 $u$、$x$，要得到增量需**自行减去设定值**。

另外：**由 DAE 转换而来的模型已经是增量输入形式，不要再调 `set_rterm`**（源码明确不推荐）。
