# 01 · 快速开始

本页带你在 15 分钟内跑通第一个 do-mpc 闭环控制程序。

---

## 一、安装

### 方式 A：pip（推荐给普通用户）

```bash
# 核心功能（MPC / MHE / 仿真 / 绘图）
pip install do-mpc

# 完整功能（额外包含 神经网络近似MPC / ONNX / OPC UA）
pip install "do-mpc[full]"
```

> **Windows / macOS 提示**：某些 shell 会把方括号当作通配符，请像上面那样加引号：`pip install "do-mpc[full]"`。

`[full]` 额外安装的内容（见 [`requirements_full.txt`](../requirements_full.txt)）：

| 包 | 用途 | 缺失时的表现 |
|---|---|---|
| `torch>2.0.0` | `do_mpc.approximateMPC` 神经网络近似 MPC | 导入该子模块时抛 `ImportError` 警告 |
| `onnx>=1.13.0` | `do_mpc.sysid.ONNXConversion` 神经网络转 CasADi | 同上 |
| `asyncua` | `do_mpc.opcua` OPC UA 实时接口 | 同上 |
| `packaging` | 版本号比较 | ⚠️ 见「踩坑」一节 |
| `ipykernel` | 运行文档中的 Notebook | 无影响 |

do-mpc 在 [`do_mpc/__init__.py`](../do_mpc/__init__.py) 中用 `importlib.util.find_spec` 探测这些可选包，并设置 `__ONNX_INSTALLED__` / `__ASYNCUA_INSTALLED__` / `__TORCH_INSTALLED__` 三个标志位。核心模块**不受**可选包缺失的影响。

### 方式 B：从源码安装（推荐给贡献者）

```bash
git clone https://github.com/do-mpc/do-mpc.git
cd do-mpc
pip install -r requirements.txt        # 仅核心
# 或
pip install -r requirements_full.txt   # 完整（含文档构建依赖见 requirements_docs.txt）
pip install -e .                        # 以可编辑模式安装
```

本仓库中的 `examples/` 脚本使用如下方式定位 do-mpc，因此**即使不安装**也能直接运行示例：

```python
rel_do_mpc_path = os.path.join('..','..')
sys.path.append(rel_do_mpc_path)
import do_mpc
```

### 方式 C：conda

仓库提供了 [`.conda.yml`](../.conda.yml) 环境描述文件，可用于创建一致的 conda 环境。

### 验证安装

```python
import do_mpc
print(do_mpc.__version__)      # 应输出 5.1.2
import casadi
print(casadi.__version__)      # 建议 >= 3.6.0
```

> **CasADi 版本警告**：若检测到 `casadi < 3.6.0`，do-mpc 会发出 `UserWarning` 并进入 `CASADI_LEGACY_MODE`。未来版本可能不再兼容旧 CasADi。

## 二、性能加速：HSL MA27 线性求解器（可选但强烈推荐）

IPOPT 的计算瓶颈是反复求解大规模稀疏对称不定线性系统。do-mpc 默认使用 **MUMPS**，但换成 **HSL MA27** 通常能带来显著提速。

```python
mpc.settings.set_linear_solver("MA27")   # MHE 同理：mhe.settings.set_linear_solver("MA27")
```

### Linux 安装步骤

1. 从 [HSL 官网](http://www.hsl.rl.ac.uk/ipopt/) 获取共享库（选择个人许可）；
2. 解压到某个目录，例如 `/home/user/coinhsl/`；
3. **把 `libcoinhsl.so` 重命名为 `libhsl.so`**（CasADi 用的是旧名字）；
4. 在 `~/.bashrc` 中追加：
   ```bash
   export LD_LIBRARY_PATH="$LD_LIBRARY_PATH:/home/user/coinhsl/lib"
   ```
5. 安装 gfortran 运行时：
   ```bash
   conda install -c anaconda libgfortran
   ```

### Windows

官方建议使用 **WSL**，然后按 Linux 步骤操作。

### 排错

| 报错信息 | 原因 |
|---|---|
| `libhsl.so: cannot open shared object file` | 第 3 步重命名或第 4 步 `LD_LIBRARY_PATH` 没生效 |
| `libgfortran.so.3: cannot open shared object file` | 第 5 步没执行 |

## 三、do-mpc 的四文件模板范式

`examples/` 下几乎所有示例都遵循同一套文件组织，理解它就理解了 do-mpc 的使用方式：

```
examples/<示例名>/
├── template_model.py       # 定义系统动力学 → 返回 do_mpc.model.Model
├── template_mpc.py         # 配置控制器     → 返回 do_mpc.controller.MPC
├── template_simulator.py   # 配置仿真器     → 返回 do_mpc.simulator.Simulator
├── main.py                 # 组装闭环 + 绘图 + 主循环
└── post_processing.py      # （可选）读取 .pkl 结果离线出图
```

这种拆分的好处：**同一个 `Model` 对象被 MPC、Simulator、Estimator 共享**，模型只写一次；控制器与仿真器可以独立调参；`main.py` 只关心闭环逻辑。

> 部分示例会有变体：`template_mhe.py`（MHE 估计器）、`template_lqr.py`（LQR 控制器）、`template_ekf.py`（EKF 估计器）。

## 四、实战：CSTR 反应器鲁棒 MPC

以 [`examples/CSTR/`](../examples/CSTR) 为例，完整走一遍流程。这是一个连续搅拌釜反应器，控制目标是把产物浓度 `C_b` 稳定在 0.6 mol/l，同时反应温度 `T_R` 不得超过 140 °C，且模型参数 `alpha`、`beta` 存在不确定性。

### 步骤 1：建模 —— `template_model.py`

```python
def template_model(symvar_type='SX'):
    model_type = 'continuous'                       # 'continuous' 或 'discrete'
    model = do_mpc.model.Model(model_type, symvar_type)

    # --- 状态 ---
    C_a = model.set_variable(var_type='_x', var_name='C_a', shape=(1,1))
    C_b = model.set_variable(var_type='_x', var_name='C_b', shape=(1,1))
    T_R = model.set_variable(var_type='_x', var_name='T_R', shape=(1,1))
    T_K = model.set_variable(var_type='_x', var_name='T_K', shape=(1,1))

    # --- 输入 ---
    F     = model.set_variable(var_type='_u', var_name='F')
    Q_dot = model.set_variable(var_type='_u', var_name='Q_dot')

    # --- 不确定参数（后续用于鲁棒 MPC 场景）---
    alpha = model.set_variable(var_type='_p', var_name='alpha')
    beta  = model.set_variable(var_type='_p', var_name='beta')

    # --- 辅助表达式（会被自动记录，可用于绘图）---
    T_dif = model.set_expression(expr_name='T_dif', expr=T_R - T_K)

    # --- 中间量（不加入模型，仅本文件可见）---
    K_1 = beta  * K0_ab * exp(-E_A_ab /(T_R+273.15))
    K_2 =         K0_bc * exp(-E_A_bc /(T_R+273.15))
    K_3 =         K0_ad * exp(-alpha*E_A_ad/(T_R+273.15))

    # --- 微分方程右端 ---
    model.set_rhs('C_a', F*(C_A0 - C_a) - K_1*C_a - K_3*(C_a**2))
    model.set_rhs('C_b', -F*C_b + K_1*C_a - K_2*C_b)
    model.set_rhs('T_R', ...)
    model.set_rhs('T_K', (Q_dot + K_w*A_R*(T_dif))/(m_k*Cp_k))

    model.setup()          # ★ 必须调用，之后模型不可再修改
    return model
```

**要点**
- `set_variable` 的 `var_type` 决定了变量在整套体系中的角色，详见 [架构与核心概念](02-架构与核心概念.md#三变量类型体系)。
- `set_expression` 与 `set_meas` 的表达式会被记录进 `Data`，可直接绘图；普通 Python 变量（如 `K_1`）则不会。
- `model.setup()` 是"冻结点"，调用后再改模型会触发断言错误。

### 步骤 2：配置 MPC —— `template_mpc.py`

```python
def template_mpc(model, silence_solver=False):
    mpc = do_mpc.controller.MPC(model)

    # --- 基本设置 ---
    mpc.settings.n_horizon = 20               # 预测时域（必填）
    mpc.settings.t_step    = 0.005            # 采样周期（必填）
    mpc.settings.n_robust  = 1                # 鲁棒时域：场景树在第 1 步之后合并
    mpc.settings.open_loop = 0                # False = 每个场景独立输入
    mpc.settings.state_discretization = 'collocation'
    mpc.settings.collocation_type     = 'radau'
    mpc.settings.collocation_deg      = 2
    mpc.settings.collocation_ni       = 1
    mpc.settings.store_full_solution  = True  # 存完整预测轨迹（动画需要，占内存）
    if silence_solver:
        mpc.settings.supress_ipopt_output()

    # --- 变量缩放（对数值条件至关重要）---
    mpc.scaling['_x', 'T_R']    = 100
    mpc.scaling['_x', 'T_K']    = 100
    mpc.scaling['_u', 'Q_dot']  = 2000
    mpc.scaling['_u', 'F']      = 100

    # --- 目标函数 ---
    mterm = (model.x['C_b'] - 0.6)**2         # 终端代价
    lterm = (model.x['C_b'] - 0.6)**2         # 阶段代价
    mpc.set_objective(mterm=mterm, lterm=lterm)

    # --- 输入增量惩罚（抑制抖动）---
    mpc.set_rterm(F=0.1, Q_dot=1e-3)

    # --- 硬约束 ---
    mpc.bounds['lower', '_x', 'C_a'] = 0.1
    mpc.bounds['upper', '_x', 'C_a'] = 2
    mpc.bounds['lower', '_u', 'F']   = 5
    mpc.bounds['upper', '_u', 'F']   = 100
    # ...

    # --- 软约束（温度上限，允许有限违反）---
    mpc.set_nl_cons('T_R', model.x['T_R'], ub=140,
                    soft_constraint=True, penalty_term_cons=1e2)

    # --- 鲁棒 MPC：声明参数的不确定取值集合 ---
    mpc.set_uncertainty_values(alpha=np.array([1., 1.05, 0.95]),
                               beta =np.array([1., 1.1 , 0.9 ]))

    mpc.setup()
    return mpc
```

**要点**
- `mpc.settings.*` 是 v4.5.1 引入的新接口（dataclass），可打印、IDE 有补全；旧的 `mpc.set_param(**dict)` 仍可用，内部会转调新接口。
- `bounds` / `scaling` 是**幂索引属性** (`IndexedProperty`)，用 `['lower', '_x', '名称']` 这样的多元组索引。
- `set_uncertainty_values` 是高层 API；如需完全自定义场景，用 `get_p_template(n_combinations)` + `set_p_fun`（低层 API）。

### 步骤 3：配置仿真器 —— `template_simulator.py`

```python
def template_simulator(model):
    simulator = do_mpc.simulator.Simulator(model)

    simulator.set_param(
        integration_tool='cvodes',   # 'cvodes'（ODE）或 'idas'（DAE）
        abstol=1e-10,
        reltol=1e-10,
        t_step=0.005,                # 通常与 mpc.settings.t_step 一致
    )

    # 时变参数：仿真器只需要"当前一个值"，不是序列
    tvp_num = simulator.get_tvp_template()
    def tvp_fun(t_now):
        return tvp_num
    simulator.set_tvp_fun(tvp_fun)

    # 固定参数：这里取名义值 1（与 MPC 中的不确定集合区分开）
    p_num = simulator.get_p_template()
    p_num['alpha'] = 1
    p_num['beta']  = 1
    def p_fun(t_now):
        return p_num
    simulator.set_p_fun(p_fun)

    simulator.setup()
    return simulator
```

> **关键概念**：仿真器扮演"真实世界"，因此它的 `p_fun` 应返回**真实**参数值；而 MPC 里的 `set_uncertainty_values` 表达的是控制器**认知到的不确定性**。两者不同才构成一个有意义的鲁棒控制测试。

### 步骤 4：组装闭环 —— `main.py`

```python
model     = template_model()
mpc       = template_mpc(model)
simulator = template_simulator(model)
estimator = do_mpc.estimator.StateFeedback(model)   # 简化：假设状态全可测

# 初值
x0 = np.array([0.8, 0.5, 134.14, 130.0]).reshape(-1,1)
mpc.x0 = x0
simulator.x0 = x0
mpc.set_initial_guess()
simulator.set_initial_guess()

# 绘图
graphics = do_mpc.graphics.Graphics(mpc.data)
fig, ax = plt.subplots(5, sharex=True)
graphics.add_line(var_type='_x',   var_name='C_a',    axis=ax[0])
graphics.add_line(var_type='_aux', var_name='T_dif',  axis=ax[2])
graphics.add_line(var_type='_u',   var_name='Q_dot',  axis=ax[3])
# ...

timer = do_mpc.tools.Timer()
for k in range(50):
    timer.tic()
    u0     = mpc.make_step(x0)
    timer.toc()
    y_next = simulator.make_step(u0)
    x0     = estimator.make_step(y_next)

    graphics.plot_results(t_ind=k)
    graphics.plot_predictions(t_ind=k)
    graphics.reset_axes()
    plt.show(); plt.pause(0.01)

timer.info()      # 打印平均/最坏求解耗时
timer.hist()      # 画出耗时直方图

# 保存结果供离线分析
do_mpc.data.save_results([mpc, simulator], 'CSTR_robust_MPC')
```

运行：

```bash
cd examples/CSTR
python main.py
```

## 五、快速自检清单

新写一个 do-mpc 程序时，按顺序检查：

- [ ] `model.setup()` 已调用，且在所有 `set_variable` / `set_rhs` 之后
- [ ] `mpc.settings.t_step` 与 `mpc.settings.n_horizon` 都已设置（**唯一两个必填项**）
- [ ] 所有输入都有 `bounds`，否则默认是 `±inf`
- [ ] 量级差异大的变量（温度 vs 浓度）设置了 `scaling`
- [ ] `mpc.x0` / `simulator.x0` 已赋值，且调用了 `set_initial_guess()`
- [ ] `simulator.settings.t_step == mpc.settings.t_step`
- [ ] 若模型含 `_tvp` 或 `_p`，MPC / Simulator / MHE **各自**都设置了 `set_tvp_fun` / `set_p_fun`
- [ ] 含代数变量 `_z` 的连续模型：`simulator` 的 `integration_tool` 设为 `'idas'`
- [ ] 调用 `make_step` 前，`setup()` 已完成
